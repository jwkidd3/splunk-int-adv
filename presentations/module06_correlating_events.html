Module 6

Correlating Events

Splunk Intermediate / Advanced

🔗 Why Correlate

  • A single event rarely tells a story — a sequence does
  • One customer's visit is dozens of events sharing a session ID
  • One intrusion attempt is many failed logins from one address
  • Correlation groups related events so you can ask about the group
The question changes from “how many requests?” to “how many visits, how long did they last, and how many ended in a purchase?”

🤝 The transaction Command

  • Groups events sharing one or more field values
  • Produces one result per group
  • Adds duration and eventcount
  • _raw of the group is every member concatenated
index=web sourcetype=access_combined
| transaction JSESSIONID
| table JSESSIONID, clientip, action,
        duration, eventcount

Constraining the group

OptionMeaning
maxspanLongest the whole group may last
maxpauseLongest gap allowed between events
maxeventsMost events in one group
startswithEvent that opens a group
endswithEvent that closes a group
Without constraints, two unrelated visits that reuse a session ID weeks apart become one transaction lasting a fortnight.

⏱️ A Realistic Transaction

index=web sourcetype=access_combined
| transaction JSESSIONID
    startswith=(action="addtocart")
    endswith=(action="purchase")
    maxspan=30m maxpause=5m
| eval minutes = round(duration/60, 1)
| table JSESSIONID, clientip, minutes, eventcount
  • Only sessions that got from cart to checkout survive
  • maxspan rules out an abandoned cart revisited later
  • maxpause rules out a session left open over lunch
search after transaction filters the groups. Before it, you filter the events that are available to be grouped — and may remove the ones that would have joined them up.

⚖️ transaction vs stats

Use stats

  • Almost always — it is far faster
  • You need counts, sums or distinct counts per group
  • The grouping field is a simple value
  • The data set is large
index=web sourcetype=access_combined
| stats range(_time) as duration,
        count as events,
        values(action) as actions
        by JSESSIONID

Use transaction

  • You need the events themselves, in order
  • The group is defined by a start or end marker
  • You need time-based constraints between events
  • The same ID is reused and must be split by time
transaction is memory-bound and has a configured limit on group size. On a wide time range it will silently drop groups rather than fail.
